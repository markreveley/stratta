# For the operator

Agents get an `AGENTS.md`. This is the same idea pointed the other way: notes for the
person driving them. It is short on purpose, and it is a set of things to notice, not
rules to follow.

It was drafted by an agent on 2026-11-26, from one long thread in which the operator and
the agent traced how a guess became a rule in this repository's plans. The operator
should rewrite it in his own words; until then it is a draft.

## What happened

Within two days of this repository's first commit it had nineteen plans, a nineteen-step
list, and no reported day of work with a real agent. Several plans rested on an idea
nobody had stated: that the operator's time spent answering an agent's permission
requests is overhead. That idea got a number (how long a request waits), the number got
thresholds, and the thresholds were written as instructions. The operator, once asked,
said he finds the requests appropriate and informative.

No step was careless. The operator calls the result inherited bureaucracy: a limit that
a later agent takes as decided, when it was an earlier agent's guess.

## Things to notice in how you ask

- **"Where is the value?" invites a metric.** An agent given an open question looks for
  a direction and a way to measure it, and will supply both. "What did you notice?" and
  "what would you try first?" get a different answer.
- **Say which kind of thing you want.** A need you have met, a question you want
  answered, or an idea you want to try because it interests you. All three are good
  reasons. An agent that is not told will write up the third as the first.
- **Say what you have actually experienced.** The agent cannot see it. A sentence like
  "these requests are useful to me" would have removed three plans' premise on the first
  day.
- **Say what is yours to decide.** When to stop, what counts as success, and what comes
  first. If you do not claim them, an agent will fill them in, in the same voice it uses
  for facts.

## Things to notice in what comes back

- **A premise you did not state.** When a plan says what you want or what costs you
  something, ask where that came from.
- **A number with a target.** Ask what it assumes about you, and who set the line.
- **"Do not", "only if", "stop when".** Ask who decided. If the answer is an agent, it
  is a suggestion.
- **Plans that justify each other.** "This pays for that" is not a reason for either.
- **Agreement that came easily.** Nodding at something plausible is how a premise gets
  in. Being wanted is not the same as being needed, and an agent will build what you
  seem to want.
- **Plans ahead of use.** The fastest check on any of this is a day of real work.

## One question that worked

"What problem are we trying to solve here, where did we deduce it is a problem, and how
does it rank in the big picture?" It took one asking to find that a plan had no problem
behind it.
