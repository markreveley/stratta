Tutorial: Stratta's architecture, from the process up

About this tutorial

Stratta is a control plane for coding agents, written in Elixir. Its repository holds a working system, a list of twenty-seven next steps (next.md), and twenty-three plans that say what those steps build. The plans were in plans/ when this was written and are now under md/plans/, each in a dated folder: md/plans/2026-11-26-event-log/event-log.md is md/plans/2026-11-26-event-log/event-log.md. This tutorial is kept in the same repository, in md/docs/tutorial/. This tutorial describes nineteen of the steps and twenty-one of the plans; the eight newer steps and the two newer plans are named in section 36. This tutorial explains the concepts a reader needs in order to read that list and those plans and know, at each sentence, what is being proposed and why it has the shape it has.

It is written for one reader: someone who has worked through an introductory Elixir course, as far as a first GenServer, and knows how the BEAM holds data in memory, who has run Stratta, and who did not write most of its code. It assumes pattern matching, immutable data, folds, with, and the idea of a process with a mailbox. It assumes nothing about OTP beyond one small counter server, and nothing about Jido, agent protocols, or capability security. Each term is explained the first time it appears, in bold, and the Glossary at the end lists every term with the section that introduced it.

There are seven parts:

Part 1 describes the system as it runs today, and follows one permission request from an agent to the operator and back. Every later part explains one stretch of that journey.

Part 2 covers the runtime underneath: processes, GenServer, supervisors, registries and tasks, each shown where Stratta uses it.

Part 3 covers how a thread's state is computed and how everyone watching hears about it: a pure fold over events, and publish and subscribe.

Part 4 covers the edges of the node: the control socket, the API behind it, the agent programs outside it, the two protocols an agent can report through, and the terminal.

Part 5 covers behaviours and Jido, the framework the first planned integration is built on, the one decision that integration turns on, and the parts of Jido the plans have only begun to draw on.

Part 6 covers the ideas in the plans that are not about Elixir at all: a decision as a record, traces, policy, authority, one registry of operations, code written by a model, claims, two kinds of graph, and where a thread's files and processes live.

Part 7 goes back to next.md with all of that in hand: the dependency graph behind the list, and what each step asks the reader to know.

The tutorial describes Stratta at commit a7c451f (25 November 2026), with two exceptions: the list of plans in section 4 and all of Part 7 follow next.md and plans/ as reordered on 26 November 2026, when the operator chose to build Stratta first as a guest in a host terminal; and section 25, section 34 and the end of section 12 follow two plans added later that day. Both are as of commit 2846650. That commit also holds the one change to Stratta's code since a7c451f, the repair that section 12 describes. Every excerpt of Stratta's code shown here was compared with that commit by a script. Every excerpt of lab code is cut by the build from a file that was run, and the transcripts are kept with the tutorial. Stratta itself was not run while writing: the authoring environment had an older Elixir than Stratta requires. One of its modules was run by itself, for section 12. The Sources section says exactly what was checked and how.

Contents and how to read this

Part 1 is short and should be read first by everyone. Part 2 to Part 4 are the Elixir and OTP half; a reader who already writes OTP applications can skim them for the sentences that name Stratta's modules. Part 5 and Part 6 are the half that the plans lean on most, and Part 6 can be read without Part 5 except for sections 28, 31 and 34. Part 7 is a reference: return to it when starting a step.

Seven labs go with the text. Each is one Elixir script with its tests, a miniature of one piece of Stratta, with the parts to write left as stubs. They need Elixir and nothing else; section 39 lists them. Do a lab when its section sends you there, before reading on.

Two conventions. Today means the code at the commit above. Planned means written in a plan and not built; nothing planned is described as if it existed. Where the plans and the reference material disagree, the text says so, and section 40 collects those places.
