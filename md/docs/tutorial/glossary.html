Glossary

Every technical term this tutorial uses, A to Z, with the section that introduces it. Built from source/glossary.md; the site check confirms that each term appears in bold in the section named here.

Jump to: A · B · C · D · E · F · G · H · I · J · L · M · N · O · P · R · S · T · U · V · W

A

Action

In Jido, a module with a name, a schema for its parameters and a run/2 function. An agent's routes say which action handles which signal type. The policy plan's Phase 2 expresses each rule as one. Introduced in section 22.

Adapter

A module that tells Jido.Harness how to find and start one agent program and which optional features it has. It implements the Jido.Harness.Adapter behaviour. Stratta.DemoAdapter is one. Introduced in section 18.

Agent

In Stratta, an installed coding-agent program such as Claude Code or Codex. In Jido the word is wider: any long-lived thing that receives messages, holds state and decides what to do. Introduced in section 1.

Agent Client Protocol (ACP)

The protocol a coding agent speaks in protocol mode: JSON-RPC messages over its standard input and output, with the program that started it as the client. Introduced in section 18.

AgentServer

Jido's live form of an agent: a process, built on OTP's :gen_statem, that holds an agent value and replaces it at each commit. Introduced in section 22.

Ambient authority

A right that comes from where a program runs and who it runs as, not from anything it holds. Today the right to answer a request in Stratta is ambient: being able to open the socket. Introduced in section 29.

Append-only log

A store to which records are added and in which none is ever changed. A correction is a new record that refers to the old one. Introduced in section 26.

Application

In OTP, a unit that can be started and stopped as a whole: a set of modules and usually a function that starts a supervision tree. Any node that starts the :stratta application is a daemon. Introduced in section 8.

Attenuation

Making a weaker capability from a stronger one. A grant that can be handed on only as something strictly weaker is what makes delegation expressible. Introduced in section 29.

Attribute

A key and value attached to a span, such as the thread id or who answered. Introduced in section 27.

Authority

The right to have an action taken on your say. The authority plan makes the authority to answer a request something held and presented. Introduced in section 29.

B

Back-pressure

A slow consumer limiting a fast producer. The socket's coalescer is a mild form: it never holds more than one pending state per thread for a client. Introduced in section 14.

Behaviour

A list of functions a module may promise to provide. The promise is written @behaviour Name, and the compiler checks it. It lets code call a module chosen at run time against a fixed contract. Introduced in section 21.

Biscuit

An open specification for capability tokens: verified with a public key, and attenuable offline by appending restrictions that cannot later be removed. The authority plan names it and says Stratta should not depend on it directly. Introduced in section 29.

Blackboard

A named board of values that several parties read and change. In Jido a reader takes a snapshot with a revision, and a change is refused if the revision has moved, which is optimistic concurrency. Introduced in section 25.

C

Call

A message to a GenServer that waits for a reply, sent with GenServer.call/3 and handled by handle_call/3. Introduced in section 6.

Callback

One of the functions a behaviour lists. handle_call/3 is a callback of GenServer. Introduced in section 21.

Capability

An unforgeable token that grants a specific right to whoever presents it. The plans call theirs a grant. Introduced in section 29.

Cast

A message to a GenServer with no reply, sent with GenServer.cast/2. ThreadServer has none. Introduced in section 6.

Child

A process started and watched by a supervisor. Introduced in section 8.

Child specification

The description a supervisor is given for one child: a module, or a module with options, from which it learns how to start and restart the child. Introduced in section 8.

Claim

In the claim-graph plan, a statement together with its grounds and what was ruled about it, written when a request is answered. Its structure comes from the daemon; one sentence comes from the agent. Introduced in section 33.

CloudEvents

A public specification for describing events with a common envelope: an id, a source, a type and data. A Jido signal follows it. Introduced in section 22.

Coalescing

Merging a burst of updates into the last one. The daemon holds the latest snapshot per thread for each client and sends it at most every 40 milliseconds. Introduced in section 14.

Coding agent

A program that carries out a request in a folder of source code by running a language model in a loop of proposed actions and their results. Introduced in section 1.

Commit

In Jido, the moment in a turn when the runtime replaces the agent with the candidate. Before it, any failure leaves the agent unchanged. After it, nothing can be undone. Introduced in section 22.

Confused deputy

A program used by one party with the authority of another. An agent-run shell command calling stratta approve makes the daemon one. Introduced in section 29.

Context window

The bounded amount of text a language model can attend to at once. Code mode exists to keep operation descriptions and large results out of it. Introduced in section 32.

Control plane

The part of a system that tells the operator what the working parts are doing and carries decisions back to them. Stratta is one for coding agents. Introduced in section 1.

Correlation

Matching a reply to its request by an id both carry. It is needed on the control socket because pushes arrive between replies. Introduced in section 15.

Cursor

A reader's position in a sequence. A reader that keeps one can stop and resume without missing or repeating anything. Introduced in section 12.

D

Daemon

A long-running program with no user interface. Stratta's is core/: it owns the agents, the threads and their history. Introduced in section 2.

Debouncing

Waiting for a quiet moment before doing expensive work, so that a burst of changes causes one write. Introduced in section 6.

Decision record

Planned: one stored value per answered request, holding the request, the answer, who answered, two times, the evidence as ids, and the ground. Introduced in section 26.

Delta

A message carrying only what changed. Stratta sends whole snapshots instead. Introduced in section 14.

Dependency graph

Steps as points, with an arrow from one to another when the second needs the first. next.md is one listing of such a graph. Introduced in section 36.

Directive

In Jido, a struct that describes an effect, such as emitting a signal or stopping the agent, returned by an action and performed later by the runtime. Introduced in section 22.

Durable run

A stored flow run by Jido.Durable, saved at the boundary of each part so that it can wait and resume. Jido documents it as needing no AgentServer. The graphs plan's spike tries one against Stratta.API. Introduced in section 25.

DynamicSupervisor

A supervisor that starts with no children and is given them while running. Stratta.ThreadSupervisor is one, with a ThreadServer per open thread. Introduced in section 9.

E

Environment

Where a thread's files and processes live. Today a worktree and a child process on the operator's machine; the environments plan names that as one implementation of a behaviour. Introduced in section 35.

Escape sequence

A run of bytes, beginning with the escape character, that instructs a terminal instead of being drawn. Introduced in section 20.

Event

A small record that something happened: a type, a sequence number, a turn and a payload. Jido.Harness turns an agent's messages into events. Introduced in section 3.

Event log

The full ordered list of events, kept as the record. Stratta does not keep one; it keeps the folded timeline. A plan of 26 November 2026 proposes one file of events for each thread. Introduced in section 12.

F

Fail closed

To fall back to the most cautious behaviour when something is wrong. A broken rule set answers nothing; a failing hook gives no decision. Introduced in section 28.

Fail open

To fall back to permitting when something is wrong. The opposite of failing closed. Introduced in section 28.

Findings

The last section of every plan, empty until its spike or first phase has run and written down what it found. Introduced in section 38.

Flow

In Jido, a named graph of calls to actions, written as data: each part names an action and says where its parameters come from. It can be checked before it runs and stored as JSON. Introduced in section 25.

Flow wait

A part of a flow that suspends it until an event arrives or a time passes. The waiting flow saves its position and holds no process. Introduced in section 25.

Framing

The rule by which a stream of bytes is divided into messages. Stratta's is a length prefix. Introduced in section 15.

Front end

A user interface that shows what the daemon holds and sends it commands. Stratta has two: the app in gui/ and the stratta command in tui/. Introduced in section 2.

G

Gate

A phase whose result decides whether the rest of a plan happens at all. Introduced in section 38.

GenServer

OTP's standard pattern for a process that keeps state and handles one message at a time through callbacks you write. Introduced in section 6.

Grant

The authority plan's capability: something an answer must present. First a local secret, later narrowed, signed, and verifiable across machines. Introduced in section 29.

Grapheme

What a reader sees as one character, however many code points encode it. The composer plan keeps its cursor as a grapheme index. Introduced in section 20.

H

Hand-off

Continuing a thread under a different agent in the same folder. Today the new thread is seeded with the tail of the old transcript. Introduced in section 33.

Headless thread

A thread in which the daemon runs the agent in protocol mode and Stratta draws everything. Every thread is headless today. Introduced in section 18.

Hook

A command an agent runs at a named moment in its own work, passing a description of the moment and, for some moments, reading a decision back. Introduced in section 19.

I

Idempotent

Able to be done any number of times with the same result as once. ensure_started/1 is. Introduced in section 9.

J

Jido

A framework for building agents on the BEAM. The policy plan uses it for one job: answering permission requests. Introduced in section 22.

JSON-RPC

A convention for requests and responses as JSON objects: a request has a method, parameters and an id; a response carries the same id. Introduced in section 18.

L

Length prefix

Framing in which each message is preceded by its length. Stratta's is four bytes, handled by the runtime's packet: 4 option. Introduced in section 15.

Let it crash

The habit of handling only the failures code can do something useful about, and letting a supervisor replace a process that meets any other. Introduced in section 7.

Link

A two-way connection between processes: if either exits abnormally, the other receives an exit signal. Introduced in section 7.

M

Mailbox

The queue of messages other processes have sent to a process. Introduced in section 5.

Measure

One of five numbers the telemetry plan derives from spans: waiting time, rework, cost to a decision, automatic share and grounding. Introduced in section 27.

Monitor

A one-way watch: the watcher receives a :DOWN message when the watched process exits, and carries on. Introduced in section 7.

N

NIF

A native implemented function: foreign code loaded into the virtual machine itself. A crash in one can bring down the node, which is why agents are run behind ports instead. Introduced in section 17.

Node

A running instance of the Erlang virtual machine. Processes in one node can call each other's functions and send each other messages directly. Introduced in section 2.

Notification

A JSON-RPC request with no id, to which no response is expected. session/update is one. Introduced in section 18.

O

OpenTelemetry

The vendor-neutral standard for producing traces and metrics, with agreed names for common attributes. Introduced in section 27.

Operation

A named thing the daemon can be asked to do, with JSON-shaped arguments and result. Stratta.API has twenty-one, and the set is closed. Introduced in section 16.

Operation registry

In the behaviour-shaped UI plan, the operation specs together with the plugins a thread has: the one description from which the app, the terminal client and a model's tool list are drawn. Introduced in section 31.

Operator

The person using Stratta. Introduced in section 1.

Optimistic concurrency

Proceeding without a lock and checking at the last moment that nothing changed. The planned file.write carries a hash of what was read and is refused if the file has changed. Introduced in section 35.

OSC

Operating system command: a family of escape sequences that carry data to the terminal program and draw nothing. Introduced in section 20.

OSC 8

The escape sequence that marks a span of text as a link to a URL that is not itself displayed. Introduced in section 20.

OTLP

OpenTelemetry's wire protocol for sending traces to a tool that stores or draws them. Introduced in section 27.

P

Pane thread

Planned: a thread whose agent runs its own interface in a terminal pane and reports to the daemon through hooks. Introduced in section 19.

Permission request

An agent's question, before an action, whether it may perform it. Its turn does not continue until somebody answers. Introduced in section 1.

Pid

A process identifier. A restarted process has a new one, so Stratta finds processes by name. Introduced in section 9.

Plugin

In Jido version 3, one module that adds a capability to an agent through optional callbacks, including a state field it owns. It is what the plans call a skill. Introduced in section 23.

Policy

The set of rules that may answer a permission request without a person. Introduced in section 28.

Port

The runtime's interface to a program that is not Erlang: the program's output and exit arrive as messages to the port's owner. Introduced in section 17.

Process

A unit of execution scheduled by the virtual machine, with private memory and a mailbox. Introduced in section 5.

Process group

An operating-system grouping that lets a signal be sent to a program and its descendants together. Introduced in section 17.

Projection

A value computed by folding a list of events: one view of what happened. The timeline is the projection a chat screen needs. Introduced in section 11.

Provenance

Being traceable to where it came from. A decision record has it because every field is stated by the agent's protocol or observed by the daemon. Introduced in section 26.

Provider

The configuration that knows how to start one agent program. Introduced in section 1.

Pseudo-terminal

A pair of connected endpoints from the operating system: one behaves like a terminal to the program attached to it, the other is read and written by a controlling program. Introduced in section 20.

Publish and subscribe

The pattern in which interested processes subscribe to a named topic and a process with news broadcasts to it. PubSub for short. Introduced in section 13.

Pure core

The arrangement in which state is computed by pure functions and a small process around them receives messages, saves and broadcasts. Introduced in section 11.

Pure function

A function whose result depends only on its arguments and which changes nothing outside itself. Introduced in section 11.

R

Raw mode

A terminal setting in which every key is delivered to the program as it is pressed. Introduced in section 20.

Record graph

The graphs plan's name for what the decision, claims and context plans build together: decisions, the events behind them, claims, and the seeds made from claims. The daemon writes all of it. Introduced in section 34.

Reducer

A function of the shape (state, event) -> state. Timeline.apply_event/2 is one. Introduced in section 11.

Reduction

The unit of the scheduler's budget, roughly one function call. A process that spends its budget is switched out. Introduced in section 5.

Registry

A table from keys to processes that removes an entry when its process exits. Stratta.ThreadRegistry maps thread ids to ThreadServers; Phoenix.PubSub is built on one. Introduced in section 9.

Request name

A slot number and a letter, such as 2a, naming one permission request for good. Introduced in section 3.

Resolved path

A path turned into the absolute path it actually refers to. "Inside the folder" must be judged after resolving. Introduced in section 28.

Restart value

When a supervisor restarts a child: :permanent always, :transient only after an abnormal exit, :temporary never. ThreadServer is transient. Introduced in section 8.

Reviewer

Planned: a second thread that answers referable requests under a narrowed grant, with its reasons recorded. Introduced in section 30.

Route

In a Jido agent, the mapping from a signal type to the action that handles it. Introduced in section 22.

Route A

ThreadServer keeps the Harness session; a plain Jido agent beside it holds only the rules. Introduced in section 24.

Route B

A Jido agent with the Harness plugin owns the session and becomes the thread; ThreadServer becomes its client. Introduced in section 24.

Rule

A match on the shape of a request and an answer: allow, deny or ask. Rules are tried in order and the first match wins. Introduced in section 28.

Runic

A separate Elixir library for dataflow graphs. Jido compiles a flow to a Runic graph in order to run it. The version Jido requires is an alpha. Introduced in section 25.

S

Sandbox

An environment in which untrusted code runs with almost no ability to affect anything outside it. In code mode, where a model's scripts run. Introduced in section 32.

Search and execute

Code mode's two tools: one finds operations and returns their signatures, the other runs a script written against a library generated from the operation specs. Introduced in section 32.

Seed

The material a thread is started or continued with. It is the one part of an agent's context that Stratta controls. Introduced in section 33.

Sequence number

A number on each event that only increases within one session, so a reader can say where it has got to. Introduced in section 12.

Serialisation

Turning concurrent requests into a sequence by sending them all through one process. Introduced in section 6.

Signal

Jido's one kind of message: an envelope with a type, a source, an id and data, following CloudEvents. Introduced in section 22.

Skill

The plans' word for a Jido module with its own slice of state. In Jido version 3 that is a plugin, and "skill" means a SKILL.md file of instructions. Introduced in section 23.

Slash command

A command an agent advertises, run by sending a prompt whose text begins with /name. Introduced in section 18.

Slot

A small number a thread sits in, so that people can say 2 instead of an id. Introduced in section 3.

Snapshot

The whole current state of a thread as one value. It is what the daemon broadcasts and what it saves. Introduced in section 3.

Socket

A file-like endpoint through which two programs exchange bytes. Stratta's control socket is a Unix domain socket. Introduced in section 2.

Span

One timed operation in a trace: a name, a start, an end, a parent and attributes. Introduced in section 27.

Spec

Planned: the written description of one operation: arguments, result, one line, and whether it only reads. Introduced in section 16.

Spike

A short experiment whose product is a finding written down, not code that stays. Introduced in section 38.

Steer

To add a message to a turn that is still running. Introduced in section 1.

Strategy

Which children a supervisor restarts when one dies. :one_for_one restarts only that one. Introduced in section 8.

Supervision tree

The processes of a running system arranged by who supervises whom. Introduced in section 8.

Supervisor

A process whose only job is to start other processes and restart them when they exit. Introduced in section 8.

T

Task

A short-lived process that runs one function and exits. Introduced in section 10.

Task.Supervisor

A supervisor for tasks, so that they belong to the tree and are cleaned up with it. Introduced in section 10.

Thread

Stratta's unit: one conversation with one agent in one working folder, with everything that happened in it. Introduced in section 1.

Timeline

The ordered list of things to show for a thread, folded from events by Stratta.Timeline. Introduced in section 3.

Tool

An action an agent can take during a turn: reading a file, editing one, running a command. Introduced in section 1.

Topic

A name that processes subscribe to and broadcast on. Stratta has thread:<id>, threads and current. Introduced in section 13.

Topological order

A listing of a dependency graph that never puts a step before something it needs. Introduced in section 36.

Topology

In Jido, an agent's declaration of member agents that start when it starts, and of connections that route one member's output signals to another. Introduced in section 25.

Trace

A tree of timed operations making up one piece of work. The telemetry plan exports a thread as one. Introduced in section 27.

Trapping exits

Choosing to receive exit signals as messages. Only a process that traps exits has its terminate/2 run when a supervisor shuts it down. Introduced in section 7.

Turn

One loop of a coding agent, from a request to the point where it waits for the next. Jido uses the word for one signal handled by one agent. Introduced in section 1.

U

Unix domain socket

A socket named by a path in the file system and reachable only from the same machine. The file's permissions decide who may connect. Introduced in section 15.

V

Via tuple

A name of the form {:via, Registry, {registry, key}} that GenServer resolves through a registry at each call. Introduced in section 9.

View command

In the planned command language, a line only a front end can carry out, such as showing the diff. Introduced in section 31.

W

Work graph

The graphs plan's name for work arranged across threads: threads as points, with a line from one to another when the first one's outcome is the reason the second was started. Introduced in section 34.

Worktree

A second checkout of the same git repository in another folder. A thread can have its own so that parallel threads do not edit each other's files. Introduced in section 1.
